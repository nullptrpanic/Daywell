# 睡眠管理一期设计

用户于 2026-11-09 确认界面并授权实现。目标平台：iOS / iPadOS 17 及以上。

## 产品行为

- 底栏提供「睡眠 / 健身 / 设置」。睡眠与健身页右上角打开各自的规则。用机尚未完成，当前版本不展示其入口或占位页面；健身已实现[组数计数](fitness-counter.md)。
- 可在每个时段单独开启[清晨模式](morning-mode.md)，累计可用时长及锁定时长统一放在设置中。与对应这一轮睡眠共用应用圈选、豁免次数及逐次时长，下一轮重新计算。
- 底栏「设置」提供外观、屏幕使用时间授权、豁免名单和 Daywell 说明。外观默认跟随系统，可切换浅色或深色，选择立即应用并自动保存。
- 睡眠模块支持多个重复时间段、跨日、启用/停用、编辑与删除，不区分白天和夜间。
- 睡眠页上方状态卡提供圈选和修改入口。未授权时从这里前往全局设置。睡眠和清晨共用一组通过 Apple FamilyActivityPicker 选择的应用、类别与网站，数据只保存在设备 App Group 中。
- 应用屏蔽与网页屏蔽分开下发。圈选类别时限制相应类别的应用与网站，单独圈选网站时限制该网站；不将一个或多个类别自动升级成全部网站。Safari 未被勾选时不能认为浏览器本体已加入限制，浏览器中的网页按已选网站和类别判断。
- 保留系统圈选方式，不用固定类别数量推断「全部应用」。用户真机中的 Safari 标为 System，但圈选器未提供对应分类，因此类别全选不能代替单独选择 Safari。摘要将类别与单选 App 分开显示，例如「13 类 · 另选 1 个 App」，不把类别令牌数当作实际应用总数。
- 豁免名单供睡眠和健身共用。电话、信息等应用需要从系统列表选一次。睡眠圈选会剔除名单里的单独应用，锁定类别时也会放行这些应用。
- 豁免名单使用 `includeEntireCategory: true` 获取类别内的具体 App；选中某类最后一个 App 时，系统附带的类别标记不会阻止保存。仅持久化具体 App，网站不加入名单；界面显示所选 App 数量，超过 50 个时提示减少圈选，保留原名单。清空圈选可以清空名单。类别展开语义见 [Apple：includeEntireCategory](https://developer.apple.com/documentation/familycontrols/familyactivityselection/includeentirecategory)。
- 豁免默认每个时段 2 次，最多设置 5 次，也可设为 0 次。每次时长独立设置，预设依次为 10、5、3、2、1 分钟；设置页只显示第 1～X 次。默认递减，不强制用户自定义时长递减。每次时段发生单独计数。
- 重复星期归属开始日期，区间左闭右开。开始与结束相同、无重复日期不允许保存。
- 新增或重新开启时段时，当前时间落在区间内就立即开始；今天尚未开始的时段在今天执行，已结束的才安排到下一个符合重复星期的日期。跨夜区间沿用开始日期。旧版本在验证停用后遗留、且没有原运行轮次对应的延后标记会自动清理。
- 新增时段、修改起止时间或重复星期、重新启用时，检查与所有已保存时段的重叠，停用时段也参与检查。跨午夜计入次日，首尾相接可保存。存在重叠时拒绝保存并提示双方的时间与重复星期。旧版本已保存的冲突可停用或调整。
- 按 [锁定规则 v2.1](lock-rules-v2.md) 只保留一个锁定来源：睡眠接管清晨与运动，临时豁免仍视为原来源。旧重叠睡眠快照按开始较晚的一轮保留，其他快照持久化取消，不会在新任务结束后恢复。保存也检查仍在执行的旧快照，防止编辑后新增任务与本轮重叠。
- 豁免在时段结束时同时结束；提前恢复限制不退还次数。
- Daywell 首页和被锁应用的系统拦截页都仅在存在可用的整体豁免时显示按钮；当前有效轮次额度耗尽时隐藏豁免按钮。两处按钮统一显示「临时豁免」，时长留在说明文案中。系统页保留「好的，继续休息」。点击豁免直接调用共享豁免事务，不需要跳转主应用。
- 每个时段按自己的已使用次数选择下一次时长。说明文案展示当前轮次最多可放行的时间；后续新时段接管后按其自身额度执行。
- 时段开始时冻结时间和豁免规则。修改圈选时，新增应用、类别及网站立即并入正在运行的锁定，移除项只影响下一轮；修改不改变当前额度、豁免截止时间或时段结束时间。单个运行轮次内新增合并超过 50 个令牌时拒绝保存，保留当前配置和限制；不同轮次的有效快照合并后超过 50 时分批下发，不截断或清空。编辑时间或删除时段时，新配置从后续时段生效。
- 首页的临时豁免确认提示直接附着于「临时豁免」按钮，由系统按剩余空间显示在按钮上方或下方，不以整个页面作为弹出锚点。
- 用列表开关或编辑页停用正在锁定的时段时，需手动输入 App 生成的 6 位验证码。验证通过后立即结束本轮锁定，同时停用后续重复。验证码只确认发起操作时的锁定轮次。随本轮准备的清晨锁定也会取消。
- 首次启动为空配置，不把界面示例当作用户设置。不推断或记录实际睡眠时长。

## 组件与数据流

`DaywellCore` 是仅依赖 Foundation 的本地 Swift Package，负责日历规则、每次发生的状态、豁免事务与跨进程文件存储。可用 SwiftPM 在 macOS 测试。

SwiftUI 应用负责底栏导航、iPhone 单列 / iPad 双列、编辑器、系统应用选择器、授权及状态反馈。功能页右上角打开规则设置弹出页，完成后保留原 Tab。睡眠设置包含清晨与豁免，健身设置包含目标组数和组间休息。主应用与三个 Screen Time 扩展共用 DaywellCore、App Group 和系统适配器，使用 FamilyControls、DeviceActivity 和 ManagedSettings。Shield Configuration 读取共享额度决定是否提供豁免；Shield Action 执行同一份豁免事务，「继续休息」关闭被锁应用。

配置和运行状态统一写入 App Group 的一个版本化 JSON 文件，通过文件锁和原子替换序列化主应用与扩展的写入。读取损坏数据时报告错误，不静默重置额度；读取执行记录时先校验日期范围和先后顺序，避免异常日期在生成记录或监测编号时发生整数溢出。应用圈选仅以系统提供的不透明 token 编码保存。

读取使用原子替换后的完整快照，不等待正在下发限制的写操作，避免系统锁定页读取状态时与写入者互相等待。只有文件确实不存在时才按首次安装读取空配置；无权限或暂时不可访问时报告错误，保留上次读取的配置。写事务等待文件锁最多 1 秒，超时报告状态忙并保留已有数据。

Device Activity 扩展遇到状态锁短暂争用或同步版本变化时，在当前回调内最多尝试 3 次，重试间隔 50 ms。成功后按最新有效会话重新下发限制，去掉已结束的部分，保留其他睡眠、清晨及健身限制。不使用返回回调后可能立即被挂起的独立计时任务；长期争用、系统终止扩展或 I/O 故障仍不能保证自动恢复，前台刷新继续承担恢复入口。

DeviceActivity 的查询、注册与停止均在状态文件锁外执行，并由单独的跨进程监测锁协调，获取这把锁不等待。系统立即回调时，扩展仍可保存清晨阈值等状态；若已有监测同步在执行，回调不会再次调用监测 API，当前同步会在提交前检查最新状态并重试。豁免只有在恢复监测注册成功后才扣次并解除限制；监测忙时取消预留并保留现有锁定。读取豁免名单时也校验系统的 50 个 App 上限，避免旧数据绕过保存入口的检查。

主应用在工作 actor 上延迟创建 Screen Time 服务；已知正在运行的时段先在界面线程显示验证码，确认后仍由共享状态事务重新验证。系统的即时回调约定见 [Apple：startMonitoring](https://developer.apple.com/documentation/deviceactivity/deviceactivitycenter/startmonitoring(_:during:events:))；豁免名单上限见 [Apple：ActivityCategoryPolicy.all](https://developer.apple.com/documentation/managedsettings/shieldsettings/activitycategorypolicy/all(except:))。

主 App 冷启动时先读取已保存的圈选，再为此前已授权的用户确认本次进程的屏幕使用时间授权，随后同步锁定。启动时尚未确认的状态和暂时无法确认的错误会保留圈选，但界面不把「上次曾授权」当作本次授权成功。确认过授权后，系统状态回到 `notDetermined` 或 `denied` 时立即按已撤权处理；冷启动时明确的 `denied` 也不触发自动授权请求。

取消授权确认弹窗本身不等于撤权。在尚未确认本次授权的冷启动中，取消或暂时出错不清空应用圈选与豁免名单；之后明确授权成功时沿用保存的数据。不能把这一恢复路径用于已确认撤销授权后的失效令牌。iOS 26.5 起的 `ManagedSettingsStore.refresh` 文档仅说明刷新过期令牌，未承诺恢复已因撤权作废的令牌，当前不以此宣称撤权后免圈选。

返回前台和前台定时刷新都会检查授权。撤销后，睡眠顶部卡片恢复「尚未开启 / 开启屏幕使用时间授权」，不继续显示锁定图标、清晨图标或豁免按钮。已保存的时段、启停配置、逐次豁免规则和已用次数、清晨设置、训练组数和组间休息设置均保留，重新打开应用也不丢失。确认撤权后只清理失效的应用令牌、取消未提交的豁免预留及系统监测和限制。重新授权后需要重新圈选锁定应用和豁免名单，原时段的已用次数不重置。Apple 的 [authorizationStatus](https://developer.apple.com/documentation/familycontrols/authorizationcenter/authorizationstatus) 文档说明初始状态未确认；[FamilyActivitySelection](https://developer.apple.com/documentation/familycontrols/familyactivityselection) 文档说明撤权会使原令牌失效。

主应用的外观偏好使用 SwiftUI AppStorage 保存到本机 UserDefaults，由窗口根视图通过 preferredColorScheme 应用，复用既有动态颜色。外观偏好属于界面设置，不写入锁定规则的共享状态。主应用的 PrivacyInfo.xcprivacy 声明此 UserDefaults 用途（CA92.1）。

每个时段使用一个按日重复的系统监测计划，星期由核心规则判断。正在执行的时段保留原监测时间，结束后切换到新配置。为正在执行和接下来最先开始的时段准备一次性结束回调，避免时区变化移动每日计划后丢失原定结束时间。相同结束时间共用回调。确认结束回调已注册后才应用该时段的限制。单个监测注册失败时，仍尝试注册其他计划并应用已具备释放回调的限制，同时显示错误。

系统监测预算统一按最多 20 个计算。每日计划之外为当前/下一结束保护、单一清晨事件、一次豁免恢复、运动休息/退出及先登记后提交的替换计划预留 8 个名额；未来清晨仅预注册最近一轮。被推迟的清晨由睡眠开始回调准备，已经累计的事件不会因容量分配被重新注册。保存配置时同时检查当前计划和下一轮的必要预算；超限拒绝保存，保留原配置。旧配置超过预算时允许逐步关闭或减少任务。豁免入口和事务按本次实际计划检查容量，不用保存配置时的保守未来预算误拒当前豁免；容量不足不扣次、不先解锁。

睡眠与清晨由同一状态机决定唯一有效来源。为兼容旧大快照与清理历史限制，仍将应用、类别及网站分别按每批最多 50 个令牌分入固定名称的 ManagedSettingsStore。首批保留 `daywell.sleep`，溢出批使用 `daywell.sleep.part.N`；加上 `daywell.fitness` 总计不超过系统的 50 个命名存储。仍需限制的令牌保留在原批次，只为新增令牌分配空位，避免迁移批次时先解除旧限制再补入新限制。`sleepShieldStoreCount` 保存用过的批数，旧文件缺少该字段时按 1 读取；各进程在豁免、取消、到期、撤权时清理全部使用过的批，批数下降时也清理多余批。不会升级为全部应用或全部网站限制。此分批下发仍需授权真机验证系统实际拦截效果。

临时豁免分为预留、安排系统恢复回调、提交三个步骤。系统恢复回调安排失败时不扣次、不解除限制；中途退出最多留下未提交的预留，不产生无限期豁免。倒计时 UI 不承担后台恢复责任。

逐次时长使用可选的 durationsMinutes 字段保存五个位置，保留旧 durationMinutes 解码和旧初始化接口。旧文件中的已保存时长不被重置；全局配置读取时将次数限制为最多 5 次，但正在执行的旧时段保留原次数、时长和已消耗额度，直到该次时段结束。旧配置因此可能仍显示两次各 10 分钟，可在设置分别调整。隐藏行的自定义时长随配置保存，之后增加次数可恢复。系统拦截页由 iOS 排版并跟随设备外观，不使用主应用单独选择的外观覆盖。

两个入口并发或系统页缓存过旧时，事务重新检查可用时段、已使用次数及预留，避免重复扣次。无额度或重复请求属于业务拒绝，不标记为系统监测故障。两个 Shield 扩展新增 App Groups 能力，真机签名需要为四个 target 配置同一个组。

短于 15 分钟的时段从实际开始时间注册系统监测，监测窗口补足 15 分钟。一次性结束回调使用用户设定的结束时间。豁免也使用覆盖实际结束时间的监测窗口。圈选整类应用使用类别令牌，新保存的单独应用、类别、网站各以 50 个为上限；执行时的跨轮次并集分批下发。

## 边界与权衡

- 个人授权可由用户在系统设置撤销，本应用不提供防卸载或不可绕过的承诺。
- 系统回调与设备使用相关，不能承诺精确到秒；重启、锁屏、强退、夏令时、修改系统时间均需真机测试。
- 设备本地执行，不含账号、同步、健康数据、统计、付费、严格模式或监管者模式。
- 不增加第三方库。完整版本包含主应用、Device Activity Monitor、Shield Configuration、Shield Action 四个 target；另提供免费真机预览 target。
- 系统限制同时注册的监测数量。先清理不再需要的监测，再注册新监测；注册失败时保留配置并展示错误，不把失败显示为保护成功。
- 单独的纯 Swift 核心让重要规则能独立测试；平台权限与后台执行仍需签名后的 iPhone/iPad 验证。

## 免费真机预览

用户选择先用普通 Apple 账号体验。新增独立 DaywellPreview target / scheme，复用主应用页面与 DaywellCore，使用独立 Bundle ID 与本地 Application Support 存储。它不依赖 App Groups，不链接 Screen Time 框架，也不嵌入系统扩展，因此可使用 Personal Team 签名。

预览版允许保存多个时段、启停与编辑、配置最多五次的逐次豁免时长，以及切换外观。首页和设置明确标注预览状态；不显示授权、应用圈选或临时解锁入口，也不生成虚假的锁定状态。配置只属于预览应用，与完整版不互通。

采用单独 target 是为了将免费签名所需的产物与受限 entitlement 分开。只删除 entitlement 会使现有服务无法访问 App Group，仍会调用受限系统 API，因此不足以支持免费体验。预览服务仅复用已有配置存储与验证；完整版保持原平台适配器。编译条件只隔离依赖 FamilyControls 的界面和模型部分，不另建一套页面或状态机。

验证包括两个 target 的编译、预览产物没有屏幕使用时间框架和扩展、模拟器启动及既有核心测试。真正的 Personal Team 签名和安装需要用户登录 Apple 账号并完成设备配对；无签名架构编译不能替代这一环节。Xcode 27 与 iOS 27 支持首次无线配对，较旧系统首次需要线缆。

## 验收

核心测试覆盖跨日及星期归属、时段边界、夏令时、重叠、默认两次依次十/五分钟、用尽拒绝、每次发生重置、重启持久化、配置变更不重置额度、预留失败不解锁、损坏文件与并发写入；新增清晨窗口、一次锁定、快照及迁移测试。

模拟器验证布局和编辑流程；真机验证授权、应用圈选、后台自动锁定、豁免到期恢复、重叠及权限撤销。模拟器不能替代 Screen Time 真机验收。
