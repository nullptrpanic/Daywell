# 聚焦模式

2026-11-12：用户已确认交互原型并要求实现。沿用现有 Daywell 紫色卡片、底部导航及睡眠验证码弹窗。

- 在 Daywell 内选择一个 App，点击「开启聚焦」，用户自行回桌面打开该 App。没有自动启动第三方 App、快捷指令或第三方桌面菜单。
- 主卡片始终显示同一个主按钮：未授权且未聚焦时显示「前往设置」，进入全局设置查看授权说明；授权后显示「开启聚焦」；聚焦中显示「关闭聚焦」。全局设置与主页面使用一致的睡眠、聚焦、健身名称，介绍与授权说明都包含聚焦。
- 模拟器和预览版的应用选择入口保留运行限制提示，不生成模拟聚焦任务；「前往设置」明确表示导航，设置页说明对应环境的限制。
- 默认 90 分钟，设置页直接输入 1–1440 的整数分钟，不使用加减按钮；修改设置从下一轮生效。
- 主页面显示「聚焦模式还剩余」及小时、分钟、秒。同一主按钮开启／关闭；提前关闭使用睡眠页相同的 6 位验证码交互。验证码只针对当前这一轮，不能关闭后来开始的新一轮。
- 最近聚焦最多 5 个，按最近成功开启的顺序去重排列；仅选择不加入历史。运行时不能切换目标应用。
- 主卡片的系统应用名称／图标以所选 token 作为视图标识，选择变更时重新创建显示，避免保留旧应用名称。
- 使用系统 FamilyActivityPicker 取得隐私令牌；系统控件外观无法替换。保留系统圈选结果，不在绑定回调中强制改写成单选，避免重复回传将新选择切回旧应用。聚焦圈选展开类别中的具体 App，保存时仅允许一个 App token，忽略系统附带的类别／网站信息；仅有类别或网站不能保存。页面显示已选 App 数量，多选时立即提示并允许清空，点击「完成」也显示具体错误；取消不改变已保存的目标。更换应用需取消旧勾选，再选择新应用。最近列表使用单选圆形标记。
- 限制其他系统可限制的 App，保留目标 App、Daywell 及现有全局豁免名单；系统必要应用受 iOS 规则控制。聚焦不施加全网站限制，避免阻断所选浏览器或目标 App 内的网页；不承诺网站过滤。
- 聚焦优先级最低。睡眠、清晨或健身进入锁定状态时永久结束聚焦，不在该锁定结束后恢复。临时豁免仍保留高优先级状态，不能借此启动聚焦。
- 已存在上述锁定时，「开启聚焦」仍可点击，但会明确提示当前锁定未结束，不能开启；既不创建聚焦任务，也不改变原有锁定及豁免。主动关闭、到期或被其他锁定结束后，聚焦页恢复未聚焦状态，移除倒计时，保留所选应用、时长及最近记录；按钮按当前授权状态显示「开启聚焦」或「前往设置」。
- 健身计组、组间休息以及清晨累计用量本身不会结束聚焦；这些模块实际进入锁定状态时才结束。
- 时长、目标、最近列表及当前轮次保存在现有共享状态；启动先安装结束监控再持久化并加锁。失败不能留下无期限锁定或增加历史。撤销授权后结束聚焦并清理失效令牌，保留分钟设置。

## 实现选择

继续使用 DaywellCore + StateStore + ScreenTimeService，不增加依赖。使用 UUID 命名单次 DeviceActivity 结束监控，与现有恢复监控相同地满足最小区间要求。聚焦与睡眠／清晨互斥，复用主睡眠 ManagedSettings store，不额外占用系统 store 容量；健身接管时先设置新限制再清除旧限制。选择 App 后手动打开是已确认方案，避免维护 URL scheme 白名单或让用户逐个创建快捷指令。

自动化检查可验证状态、接口调用和监控注册顺序；真实拦截及后台回调时机仍需已授权 iPhone/iPad 验证。

API 依据：Apple 工程师给出的 [允许所选 App、限制其他 App 的示例](https://developer.apple.com/forums/thread/718169) 使用 `shield.applicationCategories = .all(except: selection.applicationTokens)`。应用限制与网站限制是 [两项独立设置](https://developer.apple.com/documentation/managedsettings/shieldsettings)，本模块只设置前者，保留目标浏览器或应用内网页的正常使用。
